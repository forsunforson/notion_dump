# Go性能调优

## 简介

对于一些服务出现内存泄露或者CPU负载率高的情况，检查代码是一部分，使用工具对代码进行性能分析，能够更快的定位问题。

## 常见问题

go程序容易出现内存泄露的点，通常在goroutine 例如发生channel阻塞，协程不能及时结束，内存占用率飙升

## gc调整

在环境变量中声明`GOGC`能够调整运行中的程序参数

## gctrace

通过修改环境变量`GODEBUG='gctrace=1'`打开Go语言自带的GC日志，向标准错误输出日志。

```plain text
gc 37 @54.129s 0%: 0.028+9.9+0.12 ms clock, 0.67+0.95/18/11+3.0 ms cpu, 7274->7274->3836 MB, 11464 MB goal, 24 P
gc 38 @59.297s 0%: 0.032+2910+0.13 ms clock, 0.78+0/2920/13+3.2 ms cpu, 11847->11847->11420 MB, 11848 MB goal, 24 P
```

gc后的第一个数字表示第几次gc @后的时间表示自程序启动的时间 %表示gc时间占程序运行整体时间的百分比 后面两项分别代表着占用时钟，用于性能分析 三个内存数字表示gc开始、结束、存活的堆容量。 goal表示下次gc的目标堆内存大小。

如果堆内存不断增加，且每次gc回收的内存很少，可能存在内存泄露。

对于在容器中运行的可执行文件，按如下步骤执行

1. `export GODEBUG='gctrace=1'`打开gc日志
1. 在`/usr/local/trpc/bin`目录下找到该服务的可执行文件
1. 假设名字为test，使用`./test 2>stderr.output`将标准错误流输出到文件
1. 这里可能会夹杂其他的错误，可以用grep进行过滤
## pprof

pprof是Go的性能分析工具，需要在代码中手动开启

```go
package mainimport (    "fmt"    "net/http"    _ "net/http/pprof")func main() {    // 开启pprof，监听6060端口请求    ip := "0.0.0.0:6060"    if err := http.ListenAndServe(ip, nil); err != nil {        fmt.Printf("start pprof failed on %s\n", ip)    }}
```

可以使用`curl http://${ip}:${port}/debug/pprof/heap > pprof.output`将结果输出至文件 再将二进制文件下载下来，使用pprof工具进行分析

使用命令`go tool pprof -inuse_space ./pprof.output`进入交互界面，分析堆 使用`top`查看前十大内存分配 使用`svg`在当前目录下输出一张svg图 使用`list ${exp}`查看与表达式相匹配的源码

使用`wget http://ip:admin_port/debug/pprof/heap?debug=1`抓去当前内存分配
使用`wget http://ip:admin_port/debug/pprof/goroutine?debug=1`查看goroutine的数量和大致信息 使用`wget http://ip:admin_port/debug/pprof/goroutine?debug=2`查看详细信息

## perf

当上述工具都不可用时，只能借助于Linux自带的性能分析工具perf

`perf top` 可以看系统当前cpu执行的性能消耗指令

`perf record -F {频率} -p {PID}` 使用某频率对pid进行采样，存储在`perf.data`文件中`perf report -i ./perf.data` 对输出的结果文件进行分析
