## HTTP解析过程

### 流程

1. 输入网址 顾名思义，在浏览器地址栏里输入网址。
1. DNS域名解析 在这步会将网址转化为IP地址，用到了DNS协议。
首先访问缓存，如果命中直接返回。
浏览器缓存 -> 系统缓存 -> 路由器缓存 -> DNS缓存
如果都失败，则开始DNS查询。这里有两种方式，迭代和递归查询。
迭代查询相当于，由DNS查询服务器不断访问每一级DNS服务器，直到获得IP地址。
递归查询相当于，由DNS查询服务器查询上一级域名服务器，如果没有结果，由该域名服务器发起请求查询它的下一级域名服务器。
1. 建立TCP连接 TCP三次握手，和服务器建立连接。
1. 发送HTTP请求
1. 服务器处理请求
1. 返回HTTP响应
1. 释放TCP连接 TCP四次挥手，断开连接。
1. 浏览器展示页面
### 数据转换

（浏览器） -> HTTP报文 -> （Web服务器） -> HTTPServletRequest -> （Servlet数据处理） -> HTTPServletResponse -> （Web服务器） -> HTTP报文 -> （浏览器）

这是从数据结构的角度看待HTTP流程，浏览器和Web服务器通信的数据结构是HTTP报文，而Web服务器将HTTP报文包装成一个HTTPServletRequest对象（以Java程序，Tomcat服务器为例子），供应用程序进行处理。当应用程序处理完后，Web服务器再将其从HTTPServletResponse对象转化为HTTP报文，发送给浏览器。浏览器解析html文件，展示多媒体文件等等，将页面展示给用户。

### Web服务器

### Apache和Tomcat的区别：

1、Apache是web服务器，Tomcat是应用（java）服务器，它只是一个servlet容器，是Apache的扩展。
2、Apache是普通服务器，本身只支持html即普通网页，Tomcat是jsp/servlet容器，用于发布jsp及java的。

Tomcat作为一个servlet容器，起到管理servlet生命周期的作用。servlet本质是一个Java程序，为单例模式。即当servlet启动时，调用它的init()方法，之后每次请求都调用service()方法，只要命中的是同一个servlet，就会调用同一个servlet实例的service()方法。当web应用终止，或tomcat停止，或装载新的servlet实例时，会调用destroy()方法，结束servlet的生命周期。

### 简单的servlet实现

只要继承了HttpServlet，并覆盖doGet()和doPost()方法，就能实现一个最简单的servlet。

```java
package org.ywy;public class ServletExample extends HttpServlet {    @Override    public void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {        System.out.println("hello world");    }    @Override    public void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {        String message = req.getParameter("msg");        System.out.println("Get Message:" + message);    }}
```

## HTTP和HTTPS的比较

### 相同点

HTTPS全称为HTTP over SSL，简单理解就是在HTTP传输上增加了SSL协议的加密能力。
### 不同点 1. 端口号不同 HTTP服务常用80端口，HTTPS服务常用443端口
2. 资源需求不同 HTTPS协议需要到CA申请证书，通常比较贵 3. 加密程度不同 HTTP通常使用明文传输，HTTPS使用SSL加密传输 4. 开销不同 HTTP使用TCP三次握手建立连接，客户端和服务器需要交换3个包；HTTPS除了TCP的三个包，还要加上SSL握手需要的9个包，所以一共是12个包

## HTTP1.0 1.1 2

### 1.0与1.1的区别

1. 缓存处理 1.0里主要使用了If-Modified-Since,Expires来做为缓存判断的标准；1.1里添加了更多例如例如Entity tag，If-Unmodified-Since, If-Match, If-None-Match等控制标签
1. 带宽使用 1.0只能传输整个对象，且不支持断点续传；1.1引入了range头域，返回206
1. 更多错误通知管理。 HTTP1.1中新增了24个错误状态响应码
1. Host头处理 HTTP1.0中认为每台服务器都绑定一个唯一的IP地址，请求头中没有传hostname；HTTP1.1的请求消息和响应消息都应支持Host头域，且请求消息中如果没有Host头域会报告一个错误
1. 长连接 HTTP 1.1支持长连接（PersistentConnection）和请求的流水线（Pipelining）处理
### 1.1与2的区别

> What is new is how the data is framed and transported between the client and the server.

1. 二进制格式 1.1版本基于文本解析；2版本基于二进制格式，更方便健壮
1. 多路复用 2版本中可以连接共享，一个request拥有一个ID，一个连接中可以有多个request，根据request ID分发到不同的服务器
1. header压缩 1.1版本每次都携带所有header信息；2版本双方各自缓存一份header信息
1. 服务端推送 2版本服务端可以主动推送数据，当用户请求该数据时，直接从缓存中获得
### HTTP3

改了底层连接，使用QUIC协议

QUIC协议是基于UDP链接实现的虚拟链接

默认加密、更快链接、网络切换更友好

### 长连接、短连接

多路复用，在一个TCP连接上，并行发送请求。2版本 长连接，指在一个TCP连接上可以连续发送多个数据包，在TCP连接保持期间，如果没有数据包发送，需要双方发检测包以维持此连接。但是后面的请求必须等前面的请求返回后才能获得发送机会。1.1版本 短连接，指通信双方有数据交互时，就建立一个TCP连接，数据发送完成后，则断开此TCP连接。1.0版本

## HTTPS访问流程

1. 浏览器发送请求，并附带一个随机数
1. 服务器收到请求后，选择非对称加密算法，把数字证书签名公钥、身份信息发送给浏览器，同时附带一个随机数
1. 浏览器接收后，验证证书的真实性，用服务器公钥发送握手信息给服务器
1. 服务器解密后，用之前的随机数计算出一个对称加密的密钥，以此加密信息并发送
1. 后续信息都用对称加密方法进行
## 问题排查

### TIME_WAIT

主动断开TCP的一方，会经过time wait状态，为了保证TCP连接的正常终止。 服务器中如果有大量的time wait，说明是服务器主动断开连接。服务器的Socket端口可以复用，只用消耗一定的资源。 可以通过设置MSL时间长度，是否开启快速端口回收来解决。
